## 三、已確認的決定（不要重新發明）

**會員領票，貴賓不領票。** 這是理監事改選，只有會員有投票權。貴賓拿到帶投票 token 的票會造成選務爭議。`tada_checkin_types.issues_ballot` 就是這道防線。

**統編一定要搭配第二道驗證。** 統一編號是財政部公開資料，誰都查得到。單憑統編就能領票等於任何人都能冒領。流程是「統編 → 選代表（**姓名遮蔽**）→ 手機末 3 碼」。姓名遮蔽讓本人認得出自己、旁人看不出是誰；末 3 碼讓「隨便選一個」失效。

**手機不需要第二道** —— 手機不是公開資訊，本身足以識別。

**不動選舉三張表。** `tada_v_members` / `tada_v_tokens` / `tada_v_votes` 之間刻意不建外鍵，這是投票匿名性的物理保證（見 `supabase/tada_voting.sql` 開頭）。原本想在 `tada_v_members` 加 `tax_id`，後來改成查主名冊取得 `member_no` 再走既有路徑，選舉表完全不必碰。

**取號機不放任何會改資料的動作。** 那台整場無人看管，能清空報到的按鈕不該在上面。清除、取消單筆一律走會務後臺（那邊有密碼驗證）。

**補登不寫進名冊。** 現場打錯字的姓名變成正式會員資料，在選舉場合是災難。`tada_checkin_pending` 獨立存放，由秘書處事後決定補進／併入／作廢。

**每位團體代表各領一張票。**（2026-08-15 確認）

## 五、實測踩過的坑

**Chromium 的 `--disable-features=Translate,TranslateUI` 擋不住翻譯列。** 實機驗證過沒用，只有頁面上的 `<meta name="google" content="notranslate">` 有效。

**Chromium 首次啟動會跳 GNOME keyring 密碼框**，整個蓋住畫面還帶出螢幕小鍵盤。加 `--password-store=basic --use-mock-keychain`。

**`overflow:hidden` 會靜靜裁切。** `scrollHeight` 不會變大、不會有捲軸，所以「頁面出血」檢查驗不出來。要逐一比對元素與容器的邊界。報到牆第一版就是這樣漏掉的。

**CSS 權重**：`@media screen` 區塊若寫在原規則之前，同權重會被後面的蓋掉。`.screen{height:714px}` 一度沒生效，改用 `html body .screen` 才行。

**從前端 JS 反推資料庫欄位會出錯。** 我用 `grep g.xxx` 推 `tada_guests` 的欄位，結果 `checked_in`、`tw`、`class` 三個都不存在，`id` 也不是 BIGINT 而是 UUID。**要驗證就直接打 PostgREST。**
